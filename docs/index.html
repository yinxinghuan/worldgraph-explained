这就是“按规则行动”。 Agent 可以提出操作；操作能否成立，以执行器的检查和结果为准。

    


    

      
把陌生名词翻成日常语言
这套世界，用什么搭起来？
可以把它想成一座小镇：
有东西、有居民、有设施，也有办事规矩。

      

        
物品类与实例品类，以及具体的那一件
“木板”是一个类。你手里这块 #wood-a 是实例。两块同款木板，仍有不同 ID。
为什么要分？系统要知道实际用了哪一件，不能凭一句“我有木板”就开工。

        
物主与持有谁拥有，谁当前能用
真人和智能体居民，都可以持有物品。租来的小锤在许可内可以使用，却不代表它永久属于你。
同一件东西，不能同时被两个人各用一次。所有权、持有和使用许可要分别说明。

        
实体与账户办事的地方，以及你和它的关系
工厂、商店、矿脉是实体，承载库存和规则。账户连接一个主体与一个实体，记录许可、交易等关系。
账户不必等于银行余额。当前规划里的支付，是具体物品的转移。

        
通用函数与 DSL做事的方法，以及每一种具体配方
通用函数处理组装所需的输入、输出、设备、损耗和时间。DSL 是按固定格式填写这些条件的规则说明。
可以增加许多配方，而不为每一种物品重写整套组装程序。超出已有能力的新机制，仍需开发。

        
Agent 与规则索引理解目标、找方法的帮手
你说想做什么，Agent 查找已发布、当前可用的操作，准备实际参数并调用。
它可以解释结果、提出建议，但不能用一句描述修改账本，也不能凭空增加一种操作。

        
事务与账本一笔受检查的变化，以及留下的记录
事务把一笔变化完整提交，或完整拒绝。账本记录实际输入、产出、持有和事件。
“消耗材料”与“收到产物”不能各说各话。重复收到请求，也不能多造一只箱子。

      

      
一个很有用的区分
方法相对稳定，
具体内容可以生长。
官方 Agent 可以辅助生成不同工艺的规则候选。规则经过约定的校验与发布，才供游玩时调用。
“能写出一段说明”与“已经可以执行”，中间还有检查。
组装方法固定的执行结构
配方 A
木板、工具、时间 → 木箱
配方 B
金属、设备、时间 → 零件
配方 C
新的投入与条件 → 新的产物
仅用于说明“同一方法、多种规则”的关系。

    


    

      
当前结构的三个支点
交换、时间、地图点。
世界里的变化有投入和产出，
事情需要时间，物品也总在某个地方。

交换：每次变化有依据
买卖是交换，生产也可以用“投入与产出”表达。消耗、折旧和新增产物，都要由规则声明。
时间：让事情在约定时刻发生
世界钟负责加工完成、运输抵达和租期到期。体力是行动资源；两者分别表达等待多久、能做多少。
地图点：让距离成为条件
地点之间有路线、耗时和运输成本。先定义连接关系与成本，再决定怎样呈现为场景；不必先模拟完整物理。

      

      
地图机制与画面还需要接起来。
“走到树旁”“靠近柜台”这样的近距离操作，仍要定义画面位置与后台条件如何对应。地点图本身并未完成这部分体验。

真人和智能体居民可以使用同一套 API。
最终结果，取决于提交时的共同状态。

先前查到，不代表现在还在。执行前重新检查，避免两人各自得到同一件物品。
重复请求，不是再做一遍。同一操作返回原来的回执，不会重复买到或重复扣除。

    


    

      
把愿景和当前范围分开看
现在先把底座跑通。
这是设计介绍，不是实现完成清单。
当前范围按 2026 年 10 月 29 日的讨论收敛。

      
当前重点
让基础经济活动成立
  • 可维护、可扩充的交换规则
  • 时间调度与地图点
  • 官方提供初期商店、工厂等设施
  • 检查资源、权限、并发和重复请求
先验证“获得资源 → 加工 → 交换 → 形成新需求”能否带来选择。
后续方向
让内容与世界逐步生长
  • 官方事件和不同主题世界
  • 用户实体、自定义工艺与物质
  • 更完整的场景呈现与空间交互
  • 法律、案件与复杂观察机制暂缓
这些内容有不同成熟度，尚未形成全部开发与运营安排。

      
用户能创造新物质，会不会破坏共同规则？
规划中的做法是保存真实投入的组成。例如用 3 石头＋2 木头＋1 铝镁合金做出 ElementX，若木头被消耗，可回收组成就只有 3 石头＋1 铝镁合金。
用户工艺可以少回收，不能超额取回。官方工艺需要金，就要先合法拆出官方金实例；不能只把 ElementX 描述成金，就当成金来用。这部分仍需完整生命周期校验。

      
Agent 能从现实里，自动生成整个世界的规则吗？
目标是让 Agent 辅助生产规则内容。起步可以从已支持的模板填写具体材料、工艺与条件，再校验并发布。
新内容需要尚未实现的能力时，仍要扩展系统。规则写得出来、系统执行得正确、玩家觉得有趣，是三个分别需要验证的问题。

      
为什么暂时不做完整的法律或物理模拟？
当前先把物品、交换、时间和地点这些共同基础做好。复杂观察与社会制度保留讨论，不作为起步前置条件。
基础模拟的深度，应由实际玩家行为决定。以后要加入新的制度或物理效果，需要明确它覆盖哪些动作，以及怎样验证结果。
